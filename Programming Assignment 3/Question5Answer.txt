(a). Given the asymptotic runtimes for the two versions of Dijkstra's Algorithm, I should expect Dijkstra’s algorithm with a binary heap to be faster when the graph is sparse. This is because the runtime of that version of Dijkstra’s algorithm is O(lg(V) * E), whereas the array version has a runtime of O(V * V). So, if the number of edges are low, then it will run faster than the array version of Dijkstra, because the lesser number of edges will make the binary heap version run faster, whereas the runtime of the array version won’t be affected at all, since it’s runtime is only dependent on the number of vertices, not edges. 

Now, if the graph is dense, then I should expect the array version to run faster than the binary heap version. This is because we are running Dijkstra’s algorithm on an undirected graph, and the maximum number of edges in a undirected graph is (V) * (V - 1) / 2. So, for dense graphs, the worst case asymptotic runtime for the binary heap version could be O(lg(V) * V * V), (note that I simply replaced the number of edges, E, with (V * V), since in a dense graph, E = V * (V-1) / 2), which will be slower than the array version’s O(V * V).
